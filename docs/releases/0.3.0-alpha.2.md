# Podcast Player 0.3.0-alpha.2

This pre-release focuses on dependable mobile playback and consistent control across the Home Assistant Companion app and desktop browsers.

## Highlights

- One server-authoritative browser playback owner prevents two connected clients from continuing separate streams.
- **Take over** moves active playback to the requesting device and stops the previous connected player.
- Pausing releases device ownership, so every client shows **Play** and the next one to start becomes the active output.
- Shared progress now stays current across phone and desktop, including foreground return and websocket reconnect.
- Background progress synchronization no longer uses Home Assistant service actions, preventing repeated failure toasts and notification vibrations.
- Passive cards display a smoothly advancing clock without writing progress every second.
- The status panel identifies active playback as **Home Assistant app** or **Web browser**.
- Android Companion system media controls are disabled by default because some Android devices generate repeated haptics when WebView media notifications refresh. Card controls and background audio remain available.

## Updating

1. Update the Podcast Player integration through HACS and restart Home Assistant.
2. Download the attached `podcast-player-card.js` file and replace the existing file under `config/www/podcast-player-card/`.
3. Set the dashboard resource to `/local/podcast-player-card/podcast-player-card.js?v=0.3.0-alpha.2`.
4. Reload the dashboard once on each client.

Existing paused ghost sessions are repaired automatically when Home Assistant starts this version.

## Known limitation

A completely suspended or offline browser cannot receive an immediate command to stop. It is prevented from saving stale progress and relinquishes stale playback state when it reconnects.
